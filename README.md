# 选题工作台 · 公众号选题雷达 + 日更流水线

一套跑在 WorkBuddy（Agent 自动化）+ 少量本地 Python 脚本上的**公众号内容生产流水线**：
每天 20:00 自动收集对标号更新 → 22:00 自动写稿 + 封面 + 推草稿箱 → 成稿与小红书图卡自动回流到一本地看板，一板看清选题池、写作进度、图卡套件。

> 本仓库是完整可复刻版：包含看板生成脚本、文章收集脚本、云版看板页面、三个定时任务的提示词全文与部署指南。所有脚本均经实机验证（连续日更运行中）。

---

## 一、整体架构（数据流）

```
┌──────────────┐   20:00   ┌────────────────────────────┐
│  选题雷达     │ ────────▶ │ data/articles.json（选题池）│
│  collect.py  │           │ 对标号文章：标题/摘要/正文/封面│
└──────────────┘           └──────────┬─────────────────┘
                                      │ 22:00 日更任务读取（借鉴标题套路/选题角度）
                                      ▼
┌──────────────────────────────────────────────────────────┐
│  日更写稿任务（gzh-daily-pipeline 技能）                    │
│  ①选题池取题 ②写稿(1200~1800字) ③ImageGen封面 ④言序建稿    │
│  ⑤推送到公众号草稿箱（只进草稿箱，绝不群发）                 │
└───────┬──────────────────────────────┬───────────────────┘
        │ ⑥成稿回流                     │ ⑦图卡自动生成
        ▼                              ▼
articles/<标题>.md            social-cards/<MMDD-短标题>/output/*.png
(frontmatter: title/date/status)      （info-card-systems 技能渲染）
        │                              │
        └──────────┬───────────────────┘
                   ▼
        ┌────────────────────┐
        │ build.py 重建看板   │
        │ → 工作台.html       │  本地：卡片看板 + 阅读进度拖拽 + 图卡墙
        └────────────────────┘  云版：工作台云版.html（云端数据库 + AI 拆解）
```

**三条主链路**：

1. **选题雷达**（每日 20:00）：搜狗微信抓对标号新文 → 去重入池 → 重建看板；
2. **日更写稿**（周一至周六 22:00）：选题池取题 → 写稿 → 封面 → 草稿箱 → 成稿/图卡双回流 → 重建看板；
3. **周日科普**（周日 20:00）：建材选材科普引流款，补上周日档，保持周更 7 篇节奏。

## 二、每日时间线

| 时间 | 任务 | 动作 | 产出 |
|---|---|---|---|
| 每天 20:00 | 选题雷达 | `collect.py` 搜狗抓取对标号（验证码自动跳过，入池自动打内容类型标签 资讯/教程/复盘/横测/清单）；连续 0 增量时切换 wechat-article-search 兜底 + `--add-url` 喂链接 | `data/articles.json` 增量、看板刷新 |
| 周一~周六 22:00 | 日更写稿 | 选题→写稿→封面→言序建稿→草稿箱→回流成稿 .md→生成小红书图卡→重建看板 | `articles/<标题>.md`、`social-cards/<MMDD-短题>/`、草稿箱待审 |
| 周日 20:00 | 周日科普款 | 同上（选题方向改为业主科普引流款） | 同上 |
| 人工（任意时间） | 审稿发布 | 到 mp.weixin.qq.com 草稿箱审核后手动群发；拖卡片管理阅读进度 | 发表权始终在人 |

**错峰补偿逻辑**（内嵌在两个任务提示词里，见第四节）：
- 选题雷达启动时检查 `articles.json` 最后更新日期，超过 1 天（电脑关机错过）→ 搜狗多翻 1 页补偿并在汇报中注明；
- 日更任务启动时检查 `articles/` 有无今天成稿：有 → 判定重复运行，只汇报不重写；昨天成稿缺失 → 把昨天未消耗选题优先纳入今天评估，仍只产出一篇并注明补上哪期。

## 三、目录结构与各文件职责

```
选题工作台/
├── collect.py               # 选题雷达收集器：搜狗抓取 + --add-url 喂链接，入池自动打内容类型标签（资讯/教程/复盘/横测/清单），收录后自动调 build.py
├── build.py                 # 看板生成器：扫描 data/ + articles/ + social-cards/ → 工作台.html
├── accounts.json            # 对标公众号列表（本仓库提供脱敏模板 accounts.example.json）
├── data/
│   └── articles.json        # 选题池主库（含 title/link/account/date/cover/digest/content/status/added）
├── articles/                # 我的成稿 .md（frontmatter: title/date/status，build.py 自动判断进度）
├── social-cards/            # 小红书图卡套件，一套一个文件夹
│   ├── README.md            # 图卡制作流程与目录约定（见本仓库 social-cards/README.md）
│   └── <MMDD-短标题>/
│       ├── index.html       # 技能产出的页面（可留可删）
│       └── output/          # 渲染 PNG（看板自动收录，取第 1 张当封面）
├── 工作台.html               # build.py 产出的本地看板（自动生成，勿手改）
└── 工作台云版.html            # 云同步版看板：WorkBuddy 登录 + 云端数据库 + AI 拆解（见本仓库脱敏版）
```

**工作台.html 看板包含四个区块**：同行在写什么（近 7 天/今天切换，点卡片开原文）· 阅读进度看板（拖拽改状态，localStorage 保存）· 小红书图文（图卡墙，自动统计页数与状态）· 我的文章（卡片/按年分组表格，按字数与 frontmatter 自动判断 调研中/写作中/已完稿）。

**工作台云版.html 增能力**：WorkBuddy 账号 OAuth 登录、选题池存云端数据库（换设备同步）、手动添加/导入本地 articles.json/导出备份、卡片上「✦ AI 拆解」流式调用免密钥大模型把文章拆成 选题角度/标题公式/结构骨架/可复用钩子/怎么用到我的号 并存回云端。

## 四、三个定时任务提示词全文

> 运行环境：WorkBuddy 自动化任务（定时触发）。`<你的公众号名>`、`<你的言序账号ID>`、`<你的公众号AppID>` 为脱敏占位，复刻时替换为自己的。所有提示词均含**保密红线**：不得出现任何真实客户/雇主/品牌方名称，案例一律匿名化。

### 4.1 选题雷达 · 每日收集对标号文章（每天 20:00，FREQ=DAILY;BYHOUR=20;BYMINUTE=0）

```
执行公众号选题雷达的每日收集任务，工作目录 <选题工作台绝对路径>：

【错峰补偿】开始时先检查 data/articles.json 最后更新日期；若距上次更新超过 1 天（上次因电脑关机错过运行），本次搜狗抓取多翻 1 页补上漏掉的时段，并在汇报中注明做了补偿。

1. 运行 `python collect.py`（搜狗微信抓取对标号最新文章，对标号列表在 accounts.json：装修/家居主力 5 个（住范儿、装修33天、好好住、在家ZAIJIA、菠萝斑马居住指南）+ AI 情报源 3 个（程序员鱼皮、数字生命卡兹克、苍何）；脚本入池时自动按标题打内容类型标签 tag：资讯/教程/复盘/横测/清单）。个别号触发验证码或 0 篇属正常，不要重试超过 2 次。
2. 若本轮新增 0 篇且已连续出现，改用 wechat-article-search 技能搜索对标号（优先装修/家居号，其次 AI 情报源）最近发布的文章，把找到的 mp.weixin.qq.com 文章链接逐条用 `python collect.py --add-url <链接>` 收录（该方式会抓标题/公众号/日期/封面/摘要并自动打标签，最可靠）。
3. collect.py 末尾会自动调用 build.py 重建看板；若未自动重建则手动运行 `python build.py`。
4. 结束后向用户简要汇报：今日新增几篇（分标签统计）、各号新增数、近7天总数、待看数。不要打开文件，不要做其他事。
```

### 4.2 日更写稿 · AI×工装设计实战（周一至周六 22:00，FREQ=DAILY;BYDAY=MO,TU,WE,TH,FR,SA;BYHOUR=22;BYMINUTE=0）

```
为微信公众号「<你的公众号名>」（言序 account_id=<你的言序账号ID>，AppID <你的公众号AppID>）创作一篇「AI×工装设计实战」栏目文章并推送到草稿箱。加载 gzh-daily-pipeline 技能并严格走全流程：
【错峰补偿】开始时先检查 <选题工作台>/articles/ 里有没有 date 为今天的成稿；若有今天的成稿说明重复运行，只做简短汇报不要重写；若昨天的成稿缺失（电脑关机错过），把昨天未消耗的选题优先纳入今天的选题评估，但仍只产出一篇，汇报中注明补上了哪期选题。
①选题（系列轮换策略）：本栏目固化为五个系列，每期评估后选择整体产出最少、当前素材最充足的系列出题——①翻车复盘（真实项目踩坑全过程+纠正方案，第一人称决策过程）②材料横评（同场景多方案摆在一起对比，给出明确否谁留谁）③预算拆解（一类材料/一道工序的钱怎么分配，给分配表）④流程揭秘（AI 介入某道设计/交付流程的完整过程+耗时对比）⑤平台落差（业主拿种草图/网图对照落地现实的差距）。选题来源按优先级：读 ~/.workbuddy/skills/gzh-daily-pipeline/references/topics-pool.md 取未用选题 → WebSearch 搜近7天热点（关键词方向：AI效果图、AI写公众号、工装设计、AI工具实测、装修避坑），按利他性×独家性×时效性自动选最优并用一句话说明理由（注明属于哪个系列）；选题入池标记已用、新发现的好选题随手追加。
【桥接·选题雷达】可读 <选题工作台>/data/articles.json（选题雷达每日收集的对标号最新文章清单，含标题/摘要/内容类型标签 tag）。只取 tag 为「复盘/横测/教程/清单」的条目提炼标题套路和选题角度，套用到工装设计选题上（只借鉴结构与写法，不抄内容），汇报中注明借鉴了哪篇；tag 为「资讯」的条目仅作行业情报参考，不作为选题本体。
②写稿：按 references/writing-rules.md 执行，1200～1800字，第一人称工装设计师+AI实践者人设，标题≤30字三秒留人，成稿过一遍去AI味六条自查，数据给得出处不编造。
保密红线：全文与选题不得出现任何真实客户/雇主/品牌方名称，案例一律匿名化（「某展厅项目」「一家建材企业」），不写可反查的地名+业态组合。
③封面（每篇必做，禁止留空）：用 ImageGen 生成 2.35:1 比例封面，图内不写中文字，内容与文章主题挂钩；压缩到 ≤2MB（推荐 1200×510 JPEG），调 get_upload_channel(scene="cover") 上传，url 填入 cover_img。
④建稿：言序 create_article，abstract≤100字且有信息量（禁"本文介绍了"），表格优先改写成段落，保存 info_id。
⑤发布：publish_article 到上述 account_id，不传 theme_id（账号默认终端矩阵）。本次为自动化运行，无需询问直接发布到草稿箱。
⑥回流选题工作台：将成稿全文保存为 <选题工作台>/articles/<文章标题>.md，文首加 frontmatter（title: 文章标题 / date: 今天日期 / status: 已完稿）。
⑦图卡自动生成（必做，无需用户触发）：加载 ~/.workbuddy/skills/info-card-systems 技能，把刚写好的稿子做成一套小红书图卡——按内容在快报体/卡片体/索引体里选型（技能内流程：拆页面→写文案→改模板），渲染 PNG 输出到 <选题工作台>/social-cards/<MMDD-短标题>/，然后运行 python build.py 重建看板。用户只负责审稿，图卡直接产出。
硬约束：只进草稿箱，绝不直接群发，发表权在用户。完成后汇报：标题、选题理由、封面说明、所用主题、发布状态、图卡套名/页数/体系，并提醒到 mp.weixin.qq.com 草稿箱审核后手动发布。
```

## 六、复刻部署指南

### ① 装脚本（5 分钟）

```bash
# 1. 克隆本仓库，把 scripts 放进你的工作台目录
git clone https://github.com/<you>/topic-workbench.git
cd topic-workbench
# 2. 复制脱敏模板为正式配置，改成你的对标号
cp accounts.example.json accounts.json
# 3. 试跑：喂一篇文章链接验证抓取链路（会自动重建看板）
python collect.py --add-url "https://mp.weixin.qq.com/s/xxxx"
# 4. 打开 工作台.html 确认四个区块都有数据
```

依赖：Python 3.8+（仅标准库，无第三方依赖）。Windows / macOS / Linux 均可。

### ② 建云版看板（可选，10 分钟）

1. 在 WorkBuddy 中开一个会话说「建一个云服务应用」，用 cloud-service 创建应用；
2. 云数据库建 `articles` 表，字段：`title`(text)、`account`(text)、`link`(text)、`cover`(text)、`digest`(text)、`content`(text)、`pub_date`(date)、`status`(text)、`analysis`(text)、`created_at`(自动)；
3. 把本仓库 `工作台云版.html` 里的 `endpoint` / `publishableKey` 占位符替换成你应用的真实值，发布为在线链接即可。

### ③ 挂自动化（核心三件套）

在 WorkBuddy 中创建定时任务（自动化），提示词直接抄第四节全文：

| 任务名 | 触发 | 提示词来源 |
|---|---|---|
| 选题雷达·每日收集对标号文章 | 每天 20:00 | §4.1 |
| 日更·AI×工装设计实战（换成你的栏目） | 周一~周六 22:00 | §4.2 |
| 周日·建材选材科普引流款 | 周日 20:00 | §4.3 |

## 七、已知限制与后续计划

**已知限制**

1. **搜狗抓取不稳定**：触发验证码时自动跳过，属预期行为；兜底链路是 wechat-article-search + `--add-url` 喂链接（最可靠）。本机若挂系统代理，collect.py 已内置直连绕过。
2. **封面风格提示词与技能规则可能漂移**：日更提示词里的封面风格描述是快照，实际以 gzh-daily-pipeline 技能内最新封面规则为准（技能规则优先级更高）。
3. **图卡渲染依赖 Node**：info-card-systems 的 render.mjs 需要 Node.js 环境；PNG 输出到 `output/` 子目录也能被看板递归收录。
4. **云版看板的 AI 拆解**依赖平台免密钥模型额度，额度不足时会在界面明确报错，不影响本地版。
5. **周日任务有有效期字段**：创建时若设了 validUntil，到期后任务不再触发，需在自动化列表里续期。
6. **阅读进度看板（本地版）**状态存浏览器 localStorage，换浏览器不同步——要跨设备用云版。

**后续计划**

- [ ] 数据回流增强：公众号发表后把阅读数据拉回看板，形成「选题→发布→数据」闭环；
- [ ] 选题池智能去重：对已写选题做语义查重，避免角度撞车；
- [ ] 图卡自动发布：对接小红书/图虫等平台的发布通道；
- [ ] 看板增加周报视图：按周聚合写作量、选题命中与阅读进度；
- [ ] collect.py 增加并发与重试策略，降低对标号漏抓率。
